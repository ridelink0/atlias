Both projects use MIT licensing. These changes use the architectural ideas and Atlias's existing code; no third-party implementation was copied.

The default-off `flags.taskContext` applies requirements-first packing to both Claude Code and Codex prompt hooks. It includes small whole files explicitly named in the prompt and static local JavaScript imports recognized by its bounded pattern matcher. Real paths are deduplicated; hidden, credential, external, binary and oversized files are excluded. A source group is rejected as a whole if a recognized prerequisite cannot fit. The rendered pack is capped at 10,000 characters and eight files, with omissions stated. Existing graph answers keep priority. This is Atlias's own implementation, not a general JavaScript/TypeScript parser or the reference's module engine. Native measured outcomes, exact source and limitations are recorded in the [task-context report](../evals/results/native-codex/codex-atlias-pack-2026-09-30/REPORT.md); they do not establish Claude-model savings or lower peak context.

Following the reference's latency-measurement approach, a local Windows Node hook probe ran seven fresh sessions per event. PreToolUse took103–155ms, PostToolUse102–170ms and prompt104–158ms. This does not explain long pending-cell waits and does not justify a hook-dispatch rewrite. The installed-block trial retained eleven one-second polls and3.332x input; the later [wait-only study](../evals/results/native-codex/codex-atlias-wait-2026-09-30/REPORT.md) and [on-demand study](../evals/results/native-codex/codex-atlias-context-2026-09-30/REPORT.md) remained more expensive. All outcomes stay published; attribution to a single instruction is unproven.

Native startup inspection also confirms the lean home instruction block and SessionStart brief reached Codex. Its --ignore-rules option only skips execpolicy .rules, according to the installed CLI's help. This corrects the earlier uncertainty in the trial notes.

The working Codex installation also registered Atlias's native hooks and the global hooks written by `install --codex`, producing two startup briefs. The lean install stages reuse of native registration only after the native CLI reports the plugin enabled, its runtime source matches this copy, the event matcher covers every tool, and a configured native trust record exists. Other hooks and any unverified events retain their global registration. An isolated native CLI install reused eight events and retained one global PostToolUse handler because its native matcher is narrower. The initial smoke test incorrectly expected nine reused events; inspection confirmed that retaining the ninth was required, and the corrected audit passed. The installed older native copy does not qualify; it still contains the host-detection defect. No live configuration has been changed, and single startup delivery and model-token effects remain unverified. This applies the references' small-surface principle without claiming their hook dispatcher or notification engine.
