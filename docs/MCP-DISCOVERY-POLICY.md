# Gev's optional MCP discovery candidate

The downloaded Claude Harness selector and prerequisite budgeter load knowledge only when selected and keep unchanged hashes from being resent. Gray's read deduplication consumes its receipt once and restores a full read, rather than permanently hiding source. Claude's NEXTGEN-5 synthesis identifies fixed tool listings as overhead, and NEXTGEN-2 warns that changing schemas during a session invalidates a stable prefix. This candidate applies selective loading to Atlias operation schemas without claiming to control native stock tools or rewrite their transcript.

`flags.mcpDiscovery` is off by default. An isolated profile can enable it with `ATLIAS_FLAG_MCP_DISCOVERY=1`. The MCP catalog then exposes one fixed `harness` operation: `list` returns operation names and descriptions; `describe` returns an original complete schema; `call` validates declared required fields/types/enums and dispatches the original implementation. All ten original operations remain callable. Normal Codex/Claude tools remain in the host. Original additional argument properties remain accepted. Discovery never executes an operation. Invalid routes, recursion and invalid inputs return errors.

Codex installation forwards the flag explicitly to its MCP child. The installed bbf6 snapshot and all global settings stay unchanged. A fresh native connection must verify activation. The 99 scripted controls prove routing, schema preservation and server resilience, with zero models. Extra discovery calls may outweigh startup savings.
