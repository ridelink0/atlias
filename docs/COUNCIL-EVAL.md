# Experimental eval council for Gev

The eval council is implemented and off by default. Enable only for an explicitly measured arm with `ATLIAS_FLAG_COUNCIL=1`; ordinary native Claude Code and Codex sessions do not acquire council retries. The saved research dropped the exec/sandbox hook, so this implementation changes only `atlias eval`.

After the original attempt, a seeded visible check must explicitly fail before retries can run. The selector is pinned before any model call. Passing, absent, model-created, timed-out or unfinished selectors spend no council retry. Up to two fresh workspaces run sequentially with the original prompt, state reset and identical task budget. Previous conversations and failure feedback are not forwarded. Selection stops at the first passing candidate whose seeded selector and protected files retain their bytes. If none wins, the original workspace is graded. Hidden graders arrive only after selection; a visible winner can still fail them.

Each row includes the original and retry candidates under `council`, recording `ran`, `chosen`, visible pass, tampering and measured character/input/output cost. Aggregate rounds, edit counters and token logs include every attempt. Missing or partial provider measurements propagate an unknown total rather than implying a saving. The selected direct-mode diagnostic describes that candidate; aggregate row counters include the original too. Workspace creation and cleanup errors are retained. Failed original workspaces remain available; non-winning retries are removed unless `keep` is set. A locked winning workspace retains its real path.

The prerequisite used three complete saved Atlias reports on 252 shared task IDs. Oracle replay gained 39.67 mean solves, above the six-flip floor, but predicts **1.45x input tokens per solved task**. It uses hidden-grader outcomes and therefore cannot establish real visible-check recovery or savings. See the [original reports and limitations](../evals/results/round5/pc-mt-three-repeats-2026-09-30/REPORT.md). A real council model arm must wait for the existing single GPU chain; do not launch a duplicate worker.

Functional verification covers fresh recovery, stop-on-first-pass, every attempted cost, no-selector/default-off behavior, hidden-grader isolation and no-winner retention. The adversarial pass covers edited selectors even outside `task.protect`, hidden failure after visible success, real timeouts, partial missing usage, provider failure, workspace creation failure and locked cleanup paths. Loop checks run with both `claude` and `codex` engine labels; direct-mode checks also run. These are scripted chats with real files and processes, **not native Claude/Codex model measurements**.

The full Windows suite passed **1,491/1,491 checks across 217 suites**. An earlier full run failed the existing cached-miss timing threshold under load; isolated testing then exposed fixture setup that depended on earlier suites. The fixture now creates its cache directory and warms the brief before measuring the warm path. Original 150ms/1000ms thresholds remain unchanged; the isolated seven checks and fresh full suite passed. Failed runs remain recorded in the local work plan.
