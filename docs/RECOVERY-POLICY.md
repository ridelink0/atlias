# Gev's recovery policy candidate

Long handoffs now prioritize complete Next, Checks run and Objective sections over bulk file/status lists. An incomplete excerpt always names the exact original note and instructs the host to read it before resuming. Short notes retain their original bytes. A section larger than the budget is omitted whole; the pointer remains. The pointer can exceed an exceptionally small soft character budget rather than truncate its identifier.

Recorded verification events now distinguish pass, fail and unknown. Missing outcomes remain unknown. Summary auditing checks text references, not semantic fidelity: filenames and command prefixes do not prove execution or preserved meaning. Next requires its complete normalized text rather than word overlap. Even a literal quote can be negated by surrounding prose, so semantic status stays unverified. Recovery supplies original state instead of treating an audit match as truth.

LF and Windows CRLF notes, invalid/fractional/zero budgets, empty/BOM notes, changed numbers and negations, oversized sections and both host brief callbacks have model-free controls. The main suite directly covers the new helper, and CI runs the targeted recovery controls.

The original full local run retained one failure: recoveryText was missing from the main test inventory despite separate controls. The corrected inventory run passed all five coverage checks. A later full local run passed 1698 checks across 228 suites before the final CRLF extension; 51 targeted controls and the affected main suites passed after that extension. Exact-source cross-platform CI must confirm the final candidate before promotion.
