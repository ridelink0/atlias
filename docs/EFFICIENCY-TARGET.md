# Atlias efficiency target for Gev

The actual goal is 20x lower usage than plain Codex or Claude Code, with exactly the same required outputs or better. The minimum milestone is 5x. Reaching the minimum does not complete the goal. Both hosts must work; a Codex result cannot establish Claude model savings.

The target means a ratio of at most0.05 (95% reduction); the minimum means at most0.20 (80% reduction). Report measured raw input, cached input and output separately, and total raw input plus output. Cached input remains input; metadata characters, projected allowance and cache discounts are not model-token evidence. Count all paid attempts and preparation calls, including unsuccessful candidates. Also report peak context rather than hiding a higher peak behind a lower total.

Quality requires the original protected contract and expected outputs for every compared task, with no Atlias regression on a task plain solves. Equal aggregate pass counts alone are insufficient. Existing graders prove their assertions, not equivalence on every possible input; state that limitation. Retain all favorable, unfavorable, invalid and unmatched rows and costs. An invalid delivery cannot become a quality success merely because its grader passed. Complete the predeclared plan and verify exact generated and full delivered context before making a target claim.

Changes require separately pinned studies with unchanged matched prompts, task identities, model, effort and grading. Existing studies must never be rerun, regraded or silently given different skill configurations. Native Claude model calls are currently unavailable; model-free adapter tests do not replace a native Claude comparison.

The source0e31-call trace audit found3 requests even on the fastest Atlias solves, with roughly19,000 input tokens in the first request. Those observed sizes are diagnostics, not architectural lower bounds or counterfactual savings. They show why a small catalog wording improvement alone cannot establish20x.

A local native Codex protocol probe identified an isolation error: directory paths in `skills.config` left64 skill entries delivered. Naming the actual `SKILL.md` files reduced this to5 builtin entries, retained the user rules and preserved tool schemas. New study plans pin `skillsIsolation: file-path-v1` for BOTH arms. Existing plans without that marker retain `directory-path-legacy`, and resuming across modes is rejected. This is a benchmark setup correction, not an Atlias-only model saving. Disabling delegation and goal tools also reduced metadata in a separate local probe, but removes capabilities; it has not been adopted as proof of equivalent functionality. The `skip_host_skill_discovery` and `code_mode_host` probes did not reduce the observed catalogs.

The next prompt-pack candidate tells both hosts to prepare edits and functional/adversarial checks from supplied snapshots in one ordered execution, while reading changed or missing files normally. This changes no source bytes in the pack and does not claim complete context for omitted files. Its effect on model rounds is unmeasured until a new pinned comparison.
