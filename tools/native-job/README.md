# Bounded native-job prototype for Gev

This opt-in prototype targets repeated context prefixes and discovery/tool rounds identified in [the pattern plan](../../docs/BENCHMARK-PATTERN-PLAN.md), using Gray's bounded jobs and Claude Harness's requirements-first packing. It does not change the installed agent, default tools or live configuration. No model savings or generic interactive feature parity is claimed.

`lib/native-job.mjs` captures complete caller-supplied task/instructions and up to32 explicitly selected UTF-8 files, rejects packets over128KiB without truncation, binds replacements to packet/source hashes and authorizes writes only to named existing files. It stages replacements outside the live workspace, checks concurrent source changes and preserves previous attempts. It never applies edits to the original workspace or executes a model-supplied command. A caller must run actual functional/adversarial checks; staging is not completion. Selection completeness and hidden-grader isolation remain the caller's responsibilities. Local checks execute model code and are not a hostile-code security sandbox.

```
node tools/native-job/test.mjs
node tools/native-job/probe.mjs <unused-out> <native-codex-exe> <native-claude-exe>
```

The probe uses isolated homes and an owned localhost fake HTTP/SSE service. It verifies exact delivered instruction text, the complete serialized packet, response parsing and source-bound edits. No inference, subscription call, real key or live user configuration is used. It deliberately reduces capabilities for bounded workers, and therefore cannot establish feature parity. Codex retained request_user_input/view_image metadata. The original tools.view_image setting was ignored by the installed CLI and was removed; custom-provider fallback metadata remains an explicit limitation even after copying the native metadata cache. Do not describe this as zero-tool, claim model metadata parity or enforce a closed-book benchmark using configuration alone.

The initial Codex fixture passed. Initial non-bare Claude startup timed out before sending a request; its empty transcript and failed run remain retained. A separate Claude-only fixture with `--bare` passed, delivering the complete packet and custom instruction text with no tools. Bare skips auth discovery/prefetch and requires an API key; here it uses an explicitly fake localhost-only key. It cannot prove subscription-mode profile delivery or bypass unavailable Claude allowance. Subscription model results and reconciled costs remain unmeasured.

The explicit `run.mjs` runner prepares without calls unless `--run` is supplied. Execution requires a fresh prescribed allowance check, explicit subscription OAuth, pinned model/effort and a new attempt directory outside the live project. It refuses API-key billing and automatic retries, records failure streams and removes copied auth. Optional caller-owned `checks.functional` and `checks.adversarial` argv run on the stage; model responses cannot supply commands. Source/stage hashes are checked before and after both passes. Completed wrong solutions remain protocol-valid and unsolved, not dropped. Passing checks verifies only that staged code against those checks; original project edits are never applied. Fifteen driver controls cover zero-call preparation, retained native-process failure, auth removal and exhausted-meter refusal;37 packet/check controls cover functional and adversarial boundaries. Native subscription activation and cost reconciliation still require actual evidence.

`tools/codexstudy/broker-run.mjs` predeclares a separate48-call comparison, twelve families with two repeats, pinned source/model/effort/contract hashes and extra behavioral cases equally graded in BOTH arms. It refuses model execution before the existing source7d48-call plan closes. The treatment carries the unchanged task string and complete nonhistorical visible source/contract files in a hashed packet; transport/custom worker instructions differ intentionally. Native baseline, all invalid/unmatched costs, protected original grading and failed solutions must be retained. The64 recipe controls passed with all12 contracts intact; preparation is not an inference result.

Profiles replace built-in instructions for this explicitly bounded worker surface, carrying every supplied user instruction unchanged inside the packet. They are not a drop-in replacement for general coding sessions; JSON transport differs from ordinary chat formatting. [Codex configuration](https://developers.openai.com/codex/config-reference/) and [Claude CLI reference](https://code.claude.com/docs/en/cli-reference) document the flags. Keep this opt-in until both hosts' delivery, checks, accounting and quality evidence pass.
